Vue → React: what transfers, what doesn’t

Oct 12, 2026 · Updated Oct 14 · 6 min · Đọc bằng tiếng Việt

I spent five years in Vue. This month I’m writing React for this portfolio. The surprising part is not JSX. It is which mental models survive the jump, and which ones you have to put down.

Reactivity

ref and useState look similar and are not. Vue tracks property access. React replaces the value. If you mutate an object in place, Vue notices and React does not.

Treat React state as a value you replace, not a graph you poke. That one sentence would have saved me two days.

Effects

watch is a scalpel. useEffect is a net. Dependency arrays are the price of admission. The Vue habit of “watch this computed and do a thing” maps to useEffect plus a carefully listed array, or, better, to deriving during render.

Data fetching

This is the cleanest transfer. TanStack Query is the same library. The cache, the keys, the invalidation — I already used them in Nuxt 3. The React version did not ask me to relearn anything except useSuspenseQuery.

components/Counter.tsx tsx 
function Counter() {
  const [n, setN] = useState(0)
  // replace, don't mutate
  return (
    <button onClick={() => setN(n + 1)}>
      {n}
    </button>
  )
}

What does not transfer

  • Single-file components with colocated styles — use modules or Tailwind, pick one
  • Directives. There is no v-if; you branch in JSX
  • The compiler doing so much that you forget about renders
Key takeaways
  • Replace state; never mutate it in place.
  • Derive during render before you reach for an effect.
  • TanStack Query is the same job in Vue and React.
  • Lifecycle names lie; the rules are different.
