Vue → React: what transfers, what doesn't

Oct 12, 2026 · Updated Oct 14 · 6 min react vue

Đọc bằng Tiếng Việt ↗

I spent five years in Vue and Nuxt. This year I am building the same kind of product — a data-dense admin plus a public site — in React and Next.js. Most of the job transferred. A few reflexes did not, and those are the ones that cost me hours.

Hưởng ứng một điều hiển nhiên: the mental model is “who owns this state?”, not “which framework am I in?”. Ở Đồng Tháp hay Hanoi, a stale list is still a stale list.

Reactivity

In Vue, ref() and computed() are the default. You mutate, the template updates. In React, state is a snapshot. If you write Vue into React you get stale closures and effects that run twice.

Treat React state as a value you replace, not an object you poke. Pinia muscle memory is the bug.

The transfer: derived data does not belong in the store. In Pinia I already pushed “server cache” into TanStack Query. In React I do the same. Local UI state stays in the component; URL state stays in the URL.

Effects

Vue's watch feels like “do this when that changes”. React's useEffect is “synchronize with something outside React”. I was over-using it for derived state. The fix was the same as a good composable: compute, don't sync.

components/Counter.tsxcopy
import { useState } from 'react'

// Vue instinct: mutate count.value++
export function Counter() {
  const [count, setCount] = useState(0)
  const doubled = count * 2 // derived, not an effect

  return (
    <button onClick={() => setCount(c => c + 1)}>
      {count} → {doubled}
    </button>
  )
}

Data fetching

This is the easy transfer. TanStack Query is the same library I used on Particula v2. Query keys, stale time, and cancelling in-flight requests with AbortController all came along.

The new piece is Next.js: Server Components fetch on the server, the admin hydrates a QueryClient. I do not put useQuery on the public case-study page. That page is a document, not an app.

app/[locale]/projects/page.tsxcopy
- const { data } = useQuery({ queryKey: ['projects'], queryFn })
+ export default async function Page({ params }: Props) {
+   const projects = await apiServer(`/public/projects?locale=${params.locale}`)
+   return <ProjectGrid projects={projects} />
+ }

What does not transfer: Vue SFCs with <script setup> colocating template and styles. React wants the same colocation, but the file is JS-shaped. I miss defineModel. I do not miss implicit provides.
