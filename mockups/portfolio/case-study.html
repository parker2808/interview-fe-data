Summary

Problem

Particula’s investor app rated 20+ real-world asset classes. Vue 2 was end-of-life, the bundle was 412kB, and weekly delivery could not stop. A rewrite in place was not an option.

Limits

Constraints

  • Zero downtime for existing ratings dashboards
  • Design tokens had to survive the Vue 2 tree until cut-over
  • The Korean and US stakeholders reviewed English copy only

Scope

Requirements

Functional

  • Ratings dashboards per asset class
  • Carbon-credit detail pages
  • Role-based views for analysts vs investors

Non-functional

  • No stale ratings after publish
  • Bundle under 280kB gzip
  • Contract tests on every PR

How

Approach

We ran a strangler. Nuxt 3 owned new routes from day one; Vue 2 kept serving the rest. Shared tokens lived in a package both apps imported. After six months the last Vue 2 route moved and we deleted v1.

Trade-offs

Key decisions

Axios → TanStack Query

Options
Keep Axios in Pinia · SWR · TanStack Query
Choice
TanStack Query
Why
Cache, retries and invalidation match “ratings must not go stale”.
Cost
Team had to unlearn store-as-server-state.

PrimeVue as the v2 primitive set

Options
Custom from scratch · PrimeVue · Naive UI
Choice
PrimeVue + a thin token layer
Why
Tables and dense filters ship weekly; we did not have time to own a kit.
Cost
Some density overrides. Worth it.

Retro

What I’d do differently

Move the design tokens first, not the first route. Two weeks of shared CSS variables would have saved a month of “why does this page look 4px off”.
